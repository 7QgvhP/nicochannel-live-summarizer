# NicoChannel Live Summarizer

ニコニコチャンネルプラスで自分が有料会員登録しているチャンネルの配信を、**自動で録音・録画してアーカイブ**し、あとから**文字起こし・要約**できる個人利用向けツールです。

配信の開始・終了を自動検知するので、起動しておけば「寝ている間の配信」も取り逃しません。過去のアーカイブ配信を取り込むこともできます。

**録るところまでと、文字起こし・要約は分かれています。**

| コマンド | 役割 |
|---|---|
| `watch` / `capture` | 録音・録画してアーカイブに保存する（ここで止まる） |
| `transcribe` | 保存したものを文字起こしする（ローカル実行・課金なし） |
| `summarize` | 文字起こしから要約を作る（API課金あり） |

録画の直後に重い文字起こしを走らせず、要約の課金も自分の判断で行えるようにするためです。

---

## できること

| 段階 | 内容 |
|---|---|
| 配信検知 | チャンネルの公開APIをポーリングし、配信の開始・終了を自動検知 |
| 手動取り込み | 過去の配信・動画を、再生時間ぶん自動で録音・録画（`capture`） |
| 録音 | 再生中のシステム音声を WASAPI ループバックで録音（追加ドライバ不要） |
| 録画 | 配信画面を GPU（NVENC）で録画し、音声と同期させて MP4 に保存 |
| 文字起こし | faster-whisper `large-v3` をローカル実行し、タイムスタンプ付きの日本語テキストに変換 |
| 要約 | Claude API で、話題ごとに区切った日本語要約を生成 |
| 実行の分離 | 文字起こし・要約は `transcribe` / `summarize` でのみ実行。手持ちの音声・動画ファイルにも使える |
| アーカイブ | 配信ごとにフォルダを作り、一覧 `INDEX.md` を自動更新 |
| 自動整理 | `cleanup` で一定日数を過ぎた音声・映像を削除（文字起こし・要約は永久保持） |
| スリープ抑止 | 監視・録画の実行中だけ PC のスリープを抑止し、配信の録り逃しを防ぐ |
| 自動再生・復旧 | 専用ブラウザで配信を自動再生し、止まったら復旧（不在時の録画向け） |
| 画面録画（単体） | `record` で今の画面をそのまま録画。配信以外にも使える |
| GUI | `gui.bat` のダブルクリックで操作画面を開く。全コマンドを実行でき、ログと録画一覧も表示 |

## 利用にあたっての前提

- 対象は**自分が正規に有料会員登録しているチャンネル**の配信に限ります。
- 生成物（録音・文字起こし・要約）は**個人のアーカイブ用途にとどめ、再配布・公開はしません。**
- 録音・録画は「実際に再生されている音声・画面をキャプチャする」方式のみです。配信の暗号化ストリームを直接取得・保存する実装は含みません。
- 画面録画で映像部分が黒くなる場合は、保護された再生経路が使われています。その場合は**回避策を取らず、`[video] enabled = false` にして音声のみに戻してください。**
- ログインは利用者自身のブラウザで行い、**本ツールは認証情報（ID/パスワード）を一切扱いません。**
- 配信検知に使うのは「配信中か」「タイトル」「予定時刻」といった公開メタデータのみです。
- 登録しているチャンネル固有のFAQ・注意書きに録画/録音に関する追加ルールがないか、事前に確認してください。
- 本ドキュメントは法律上の助言ではありません。確実性が必要な場合はご自身で確認・判断してください。

## セットアップ

> **すでにセットアップ済みの環境では、この章はまるごと飛ばして「[使い方](#使い方)」へ進んでください。**
> `.venv` フォルダがあれば構築済みです。ここは新しいPCで一から用意する場合の手順です。

### 1. 必要なもの

- Windows 10 / 11
- Python 3.11 以上
- ffmpeg（音声圧縮・画面録画用。なくても音声を WAV のまま保存する形で動作します）
- NVIDIA GPU（推奨。無い場合は自動的にCPUで動作しますが、文字起こしが数倍〜十数倍遅くなります）

### 2. インストール

**以下は1行ずつ、上から順に実行してください。** それぞれ別のコマンドで、後の行は前の行の完了が前提です。

**① ffmpeg（未導入の場合のみ）**

```powershell
winget install --id Gyan.FFmpeg -e
```

導入直後は、**新しいターミナルを開き直してください**（PATH の反映のため）。

**② 仮想環境をつくる**（数秒で終わります）

```powershell
python -m venv .venv
```

**③ 依存パッケージを入れる**（数分かかります。CUDA関連で 1.3GB ほどダウンロードします）

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

セットアップをやり直したい場合は、先に既存の仮想環境を削除してから ② を実行します。

```powershell
Remove-Item .venv -Recurse -Force
```

`.venv` を消してもアーカイブ（`archive` フォルダの録音・文字起こし・要約）と
設定（`config.toml` / `.env`）は残ります。消えるのはパッケージだけです。

### 3. APIキーの設定（要約を使う場合）

`.env.example` を `.env` にコピーし、キーを記入します。

```powershell
Copy-Item .env.example .env
notepad .env
```

キーは https://console.anthropic.com/settings/keys で取得できます。
**未設定でも動作します**（録音・録画と文字起こしは使え、`summarize` だけが実行できません）。

### 4. 監視対象チャンネルの設定

`config.toml` の `[channel] url` を書き換えます。

```toml
[channel]
url = "https://nicochannel.jp/kumonoue_yumemi"
```

## 使い方

**PowerShell** から `run.ps1` 経由で実行します（仮想環境の有効化は不要）。

```powershell
.\run.ps1 <コマンド>
```

> スクリプトの実行は Windows の既定で禁止されています。「このシステムではスクリプトの実行が無効になっているため…」と出る場合は、一度だけ次を実行して許可してください（ご自身のユーザー領域にのみ適用されます）。
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
> ```

### GUI（ボタン操作の画面）

コマンドを覚えなくても操作できる画面があります。**`gui.bat` をダブルクリック**するだけで開きます。

デスクトップにアイコンを置きたい場合は、一度だけ次を実行してください。

```powershell
.\create-shortcut.ps1
```

コマンドから開くこともできます。

```powershell
.\run.ps1 gui
```

- 左に各コマンドのボタン、右に実行ログ、下に保存済みの録画一覧が並びます
- 「アーカイブ番号」「録画する分数」などの設定は、**それを使うボタンと同じ枠の中**にあります
- 「チャンネルをブラウザで開く」で、設定したチャンネルのトップページを既定のブラウザで開けます
- 一覧から録画を選んで、そのまま**文字起こし・要約・フォルダを開く**ができます
- 実行中は**停止ボタン**で中断できます（`Ctrl+C` と同じ扱いなので、録画中でもここまでの内容が保存されます）
- 追加のインストールは不要です（tkinter は Python 標準）
- `gui.bat` とショートカットは `pythonw.exe` で起動するため、黒いコンソール窓は出ません

以降の説明はコマンドで書いていますが、**すべて GUI のボタンからも実行できます。**

### まず動作確認

```powershell
# 現在の配信状況と配信予定を表示
.\run.ps1 status

# 録音に使えるデバイスを確認
.\run.ps1 devices

# 画面録画に使えるディスプレイを確認
.\run.ps1 displays

# 専用ブラウザで実際に再生できるかを確認
.\run.ps1 browser-check --index 1
```

録音・録画そのものの確認は、短い時間を指定した `capture` で行えます。

```powershell
# 過去の配信を1分だけ取り込んでみる
.\run.ps1 capture --index 1 --minutes 1
```

結果に「⚠ 録音の 100% が無音でした」と出る場合は、録音デバイスの選択が誤っています。
`devices` で表示された名前の一部を `config.toml` の `[recorder] device_name` に設定してください。

**録画を使う場合は、本番前にこの方法で必ず確認してください。** 生成された動画を再生し、配信の映像部分が黒くなっていないかを見ます。黒くなる場合は保護された再生経路が使われているため、`config.toml` の `[video] enabled = false` にして音声のみに戻してください。

### 過去の配信・動画を取り込む

新規配信を待たずに、既存のアーカイブや動画を取り込めます。**配信のアーカイブと、チャンネルにアップロードされた動画の両方**が対象です。

```powershell
# 過去の配信と動画をすべて一覧表示（新しい順。-n で件数を絞れます）
.\run.ps1 archives

# 番号を指定して取り込む
.\run.ps1 capture --index 1

# 音声のみ取り込む（容量を抑えたいとき）
.\run.ps1 capture --index 1 --no-video
```

タイトル・配信日時・**再生時間**をAPIから取得し、その長さ＋余裕120秒で**自動停止**します。

> **配信終了直後はまだ取り込めません。** 変換処理が完了するまで再生時間を取得できず、`archives` の一覧にも「未公開」と表示されます。この状態で `capture` を実行するとエラーになるので、しばらく経ってから再度確認してください。

**手順:**

1. まず `capture` コマンドを実行する
2. 表示された配信ページをブラウザで開き、**全画面で再生を開始する**
3. 放置する。再生時間が経過すると自動停止し、アーカイブフォルダに保存される
4. あとから `transcribe` / `summarize` を実行する（実行コマンドは終了時に表示されます）

> **取り込みは実時間かかります。** 1時間47分のアーカイブなら、取り込みにも同じだけ時間がかかります（画面と音声をリアルタイムでキャプチャする方式のため）。夜間や外出中に実行するのが現実的です。

アーカイブに無い配信や、時間を自分で決めたい場合:

```powershell
# 90分間録音（タイトルは自分で指定）
.\run.ps1 capture --title "配信タイトル" --minutes 90

# Ctrl+C を押すまで録音
.\run.ps1 capture --title "配信タイトル"
```

保存先フォルダは**元の配信日**で作られるため、`watch` で録った新規配信と同じ一覧に時系列で並びます。

### 今の画面をそのまま録画する（`record`）

配信かどうかに関係なく、**ディスプレイに映っているものをそのまま**録画します。専用ブラウザは起動しません。

```powershell
# 10分間録画して archive\record_日時.mp4 に保存
.\run.ps1 record -m 10

# Ctrl+C を押すまで録画
.\run.ps1 record

# 出力先を指定 / 映像だけ記録
.\run.ps1 record -m 30 -o "C:\output\memo.mp4"
.\run.ps1 record -m 30 --no-audio
```

保存先は既定で `archive` フォルダです（`-o` で変更できます）。ただし配信のアーカイブとは別扱いで、**`INDEX.md` には載らず、`cleanup` の削除対象にもなりません。**不要になったら手動で削除してください。

画質・ディスプレイの設定は `config.toml` の `[video]` を使います（`height` / `framerate` / `display_index` / `crop`）。

**Win + G（Xbox Game Bar）との違い**

Game Bar は「特定のアプリ」を録るため、別のアプリに切り替えると録画が途切れます。本ツールは Desktop Duplication API で**ディスプレイ出力そのもの**を取るため、**アプリを切り替えても途切れません。**

その代わり、裏に回したアプリは記録されません。**画面に映っているものがそのまま記録される**ため、別のアプリに切り替えるとそのアプリが録画されます。

**録画が途中で止まった場合は警告します**

画面のロック（Win + L）、UAC の昇格ダイアログ、解像度の変更などが起きると、画面を取得できなくなって録画が停止することがあります。この場合は次の警告を出して録画を打ち切ります（自動での再開は行いません）。

```
WARNING 画面録画が途中で停止しました（ffmpeg 終了コード 1）。画面のロック、UAC ダイアログ、
        解像度の変更などで画面を取得できなくなった可能性があります。
        ここまでの映像は保存されますが、以降は記録されません。
```

この監視は `watch` / `capture` の録画中にも働きます。

> `record` は `watch` / `capture` と**同時には実行できません**。録音デバイスと GPU を奪い合って本命の録画を劣化させるためです。

### 不在時の録画（専用ブラウザによる自動再生・自動復旧）

**録画中にブラウザの再生が止まると、そのぶんが無音で記録されます。** 不在時はこれに気づけないため、専用のブラウザを使って**再生の開始と復旧まで自動化**できます。

アーカイブが残らない配信は録り直しができないため、不在時に録るならこの設定を使ってください。

#### 初回だけログインが必要です

```powershell
.\run.ps1 browser-login
```

専用のブラウザが開くので、**ご自身でログイン**してください。完了したら Enter を押すとセッションが保存されます。

- ログインはご自身の操作で行い、**本ツールは ID / パスワードを一切扱いません**
- 保存先は `.browser-profile`（Cookie を含むため共有しないでください）
- 普段の Chrome とは別プロファイルなので、通常のブラウジングには影響しません

#### 再生できるか確認する

```powershell
.\run.ps1 browser-check --index 2
```

指定したアーカイブを開き、自動操作で再生できるかを判定します。**視聴できる配信を指定してください**（プラン対象外の配信は当然再生できず、判定を誤ります）。

#### 以降は自動です

`[browser] enabled = true`（既定）であれば、`watch` / `capture` の実行時に自動で次を行います。

1. 録音を開始したあと、配信ページを専用ブラウザで開いて**再生を始める**
   - プレイヤーを**全画面**にし、**コメントを非表示**にします（[browser] fullscreen / hide_comments）
2. 録音中は音声の到達を監視し、**3分以上途切れたら再生状態を確認**
3. 止まっていれば**再生ボタンのクリック → 再読み込み**で復旧（2分間隔で再試行）

自分でブラウザを開く必要はありません。`enabled = false` にすれば従来どおり手動運用に戻ります。

> ページ上は再生中なのに音声が届かない場合は、再読み込みでは直らないため、音量や録音デバイスの確認を促す警告を出します。

### 新規配信の監視を開始する

```powershell
.\run.ps1 watch
```

配信が始まると自動的に録音・録画を開始します。
**配信をブラウザで開いて再生したままにしてください。** 再生中の音声・画面をキャプチャする方式のため、再生していないと無音・静止画面が記録されます。

配信終了を検知すると録画を止め、アーカイブフォルダに保存して監視に戻ります。**文字起こしと要約は自動では実行されません。** 保存先を指定して `transcribe` / `summarize` を実行してください（実行コマンドはログに表示されます）。

停止するには `Ctrl+C` を押します（録画中なら、そこまでの内容を保存してから終了します）。

#### 録音中の無音を検知します

録音中に**3分以上音声が届かないと警告**を出します（以降は5分おき）。

```
WARNING 12分 のあいだ音声が検出されていません。ブラウザの再生が止まっていないか確認してください: https://...
```

長時間の配信では、**ブラウザ側で再生が止まっていても録音は無音のまま進みます。** この警告に気づいたら、配信ページを開いて再生状態を確認し、止まっていれば**ページを再読み込み**してください。再生が戻れば、そこから先は正常に記録されます。

#### PCのスリープについて

**スリープ中は配信を検知できません。** スリープに入るとプロセスごと停止するためです。

そこで、`watch` や `capture` の実行中は**自動的にスリープを抑止**します（`[power] prevent_sleep`、既定で有効）。

**画面録画が有効な場合は、待機中からディスプレイの電源も維持します。** Windows の API は「画面が消えるのを防ぐ」ことはできても「消えた画面を点ける」ことはできないため、配信開始を検知してから維持を要求しても手遅れになるからです。画面を消したい場合は `[video] enabled = false` にしてください。

- 電源プランの設定そのものは変更しません。**ツールを終了すれば通常どおりスリープします。**
- 抑止が効いているかは、起動時のログ「スリープを抑止します」で確認できます。
- 管理者権限があれば `powercfg /requests` でも確認できます。

> **すでにスリープしている状態からの自動起動には対応していません。** 仮にタイマーでPCを起こせても、配信の再生はブラウザ側の操作が必要なため、無人での再生開始は現実的ではありません。**配信予定の時刻までにPCを起動し、配信ページを開いて `watch` を実行しておく**運用になります。

### 文字起こし・要約を実行する

2つのコマンドがあり、**コマンド名が「何をするか」、引数が「何に対してか」**を表します。

| コマンド | 動作 |
|---|---|
| `transcribe` | 文字起こしだけ（ローカル実行・**API課金なし**） |
| `summarize` | 要約だけ（API課金あり） |

対象はどちらも共通で、**アーカイブフォルダでも、手持ちの音声・動画ファイルでも**構いません。

```powershell
# アーカイブフォルダに対して
.\run.ps1 transcribe "archive\2026-08-17_1200_配信タイトル_smQy99EP"
.\run.ps1 summarize  "archive\2026-08-17_1200_配信タイトル_smQy99EP"

# 手持ちのファイルに対して
.\run.ps1 transcribe "C:\path\to\動画.mp4"
.\run.ps1 summarize  "C:\path\to\動画.mp4"

# 両方行う場合は続けて実行する
.\run.ps1 transcribe "archive\2026-08-17_1200_配信タイトル_smQy99EP"
.\run.ps1 summarize  "archive\2026-08-17_1200_配信タイトル_smQy99EP"

# 複数まとめて（フォルダとファイルを混ぜてもよい）
.\run.ps1 transcribe "a.mp3" "b.mp4" "archive\..."

# 実行済みでもやり直す
.\run.ps1 summarize "archive\..." --force

# 出力先・タイトルの指定（ファイル指定時）
.\run.ps1 transcribe "動画.mp4" -o "C:\output" -t "打ち合わせの記録"
```

**一度実行した工程は自動でスキップされます。** やり直したいときだけ `--force` を付けてください。

#### 典型的な使い方

```powershell
# 1. まず文字起こしだけ実行して内容を確認（課金なし）
.\run.ps1 transcribe "archive\..."

# 2. 内容に問題なければ要約する
.\run.ps1 summarize "archive\..."

# 3. モデルを変えて要約だけやり直す（文字起こしは再実行されない）
.\run.ps1 summarize "archive\..." --force
```

#### 手持ちファイルの対応形式

ffmpeg が読めるものは基本的に扱えます（実測で確認済み）。

| 種別 | 形式 |
|---|---|
| 音声 | `mp3` / `m4a` / `wav` / `flac` / `opus` |
| 動画 | `mp4` / `mkv` |

動画の場合、**映像トラックは無視され音声だけが処理されます。** 生成物は入力ファイルと同じ場所（`-o` 指定時はその場所）に置かれます。

```
動画.transcript.md     タイムスタンプ付きの文字起こし
動画.transcript.json   生データ
動画.summary.md        要約
```

> 複数指定した場合、モデルの読み込みは最初の1回だけです。2件目以降はその分速くなります。
>
> 名前が同じで拡張子だけ違うファイル（`a.mp3` と `a.mp4` など）を同じ出力先に指定した場合は、上書きを避けるため出力名に拡張子を含めます。

### その他のコマンド

```powershell
# 一覧を再生成
.\run.ps1 index

# 保持期限を過ぎた音声・映像を削除
.\run.ps1 cleanup --dry-run   # 対象の確認だけ
.\run.ps1 cleanup             # 実行
```

## 保存されるもの

```
archive/
  INDEX.md                                  ← 全配信の一覧（クリックで各ファイルへ）
  2026-08-17_1200_配信タイトル_smQy99EP/
    meta.json          配信のメタデータと処理状況
    audio.opus         録音（cleanup 実行時、既定では30日で削除）
    video.mp4          録画・音声付き（cleanup 実行時、既定では7日で削除）
    transcript.md      タイムスタンプ付きの文字起こし
    transcript.json    文字起こしの生データ（再要約に使用）
    summary.md         要約
```

音声は `audio.opus` と `video.mp4` の両方に入っています。文字起こしは `audio.opus` を使うため、
映像を削除しても再要約は可能です。

要約は次の構成で生成されます。

- 3行まとめ
- 話題ごとの内容（`### [00:12:34] 話題名` の見出し付き）
- 重要な情報・告知
- 印象的だった場面
- キーワード

## 設定（config.toml）

主なものだけ抜粋します。詳細は `config.toml` 内のコメントを参照してください。

| 項目 | 既定値 | 説明 |
|---|---|---|
| `detector.poll_interval_idle_sec` | 300 | 通常時の確認間隔（秒） |
| `detector.poll_interval_near_sec` | 30 | 配信予定が近いときの確認間隔（秒） |
| `detector.near_window_min` | 30 | 予定の何分前から密に監視するか |
| `recorder.device_name` | `""` | 空なら既定の再生デバイスを自動使用 |
| `recorder.max_hours` | 8 | 1配信あたりの最大録音時間 |
| `video.enabled` | `true` | `false` で音声のみに戻る |
| `video.display_index` | 0 | 録画するディスプレイ（`displays` で確認） |
| `video.height` | 1080 | 出力の高さ。720 にすると容量が約半分 |
| `video.framerate` | 30 | 15 に下げると容量が約半分 |
| `video.crop` | `""` | `"幅:高さ:X:Y"` で画面の一部だけ切り出し |
| `browser.enabled` | `true` | 専用ブラウザでの自動再生・自動復旧 |
| `browser.fullscreen` | `true` | 再生開始時にプレイヤーを全画面にする |
| `browser.hide_comments` | `true` | コメント（重なり表示・サイドバー）を非表示にする |
| `power.prevent_sleep` | `true` | 実行中のスリープ抑止。`false` で無効化 |
| `transcriber.model` | `large-v3` | VRAM不足なら `medium` に下げる |
| `summarizer.model` | `claude-opus-5` | 要約に使うモデル |
| `summarizer.max_tokens` | 8000 | 要約の出力上限。長い配信で途中終了する場合に増やす |
| `retention.audio_days` | 30 | 音声の保持日数（0 で永久保持） |
| `retention.video_days` | 7 | 映像の保持日数（0 で永久保持） |

## 画面録画について

**モニタ1枚を丸ごと録画します。** ウィンドウ単位のキャプチャは、ブラウザの動画がGPUで合成される都合上、映像部分が黒くなることが多いため採用していません。

そのため、配信を表示しているモニタに映っているもの（通知・タスクバー・他のウィンドウ）もそのまま記録されます。**配信は全画面表示にし、そのモニタでは他の作業をしない**運用を想定しています。画面の一部だけを残したい場合は `[video] crop` で切り出し範囲を指定できます。

映像と音声は別プロセスで記録しています（ffmpeg 単体では Windows のシステム音声を取得できないため）。開始時刻のずれは録画終了時に自動補正されます。

### 容量の目安

| 設定 | 1時間あたり | 2時間配信×月20本 |
|---|---|---|
| 1080p30（既定） | 約 1〜1.8 GB | 約 40〜70 GB |
| 720p30 | 約 0.5〜0.7 GB | 約 20〜28 GB |
| 音声のみ | 約 30 MB | 約 1.2 GB |

映像は音声の20倍以上の容量になるため、`retention.video_days` を短め（既定7日）に設定しています。

削除は `cleanup` を実行したときにだけ行われ、**文字起こしが済んでいるかは問いません。** 残しておきたい配信がある場合は、期限が来る前に `transcribe` を実行するか、`retention` の日数を延ばしてください（`0` で永久保持）。

## 費用の目安

文字起こし・録画はローカル実行のため**無料**です。課金されるのは要約のみです。

1時間の雑談配信でおよそ 2万トークン。`claude-opus-5` で **1配信あたり約26円**（月20配信で約520円）が目安です。
より安く抑えたい場合は `config.toml` の `summarizer.model` を `claude-sonnet-5`（約6割）や `claude-haiku-4-5`（約1/5）に変更できます。`summary.md` に出る概算金額も、指定したモデルの単価で計算されます。

## トラブルシューティング

**セットアップ時に `The token '&&' is not a valid statement separator` と出る**
Windows PowerShell 5.1 は `&&` に対応していません。コマンドを1行ずつ分けて実行してください（[セットアップ](#2-インストール)参照）。

**`.\run.ps1` を実行するとメモ帳などでファイルが開いてしまう**
PowerShell 以外（コマンドプロンプトやエクスプローラー）から実行しています。`.ps1` はそれらの環境では「実行するファイル」ではなく「開くファイル」として扱われます。**PowerShell を開いて実行してください。**

**「このシステムではスクリプトの実行が無効になっているため…」と出る**
実行ポリシーが既定の `Restricted` です。`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を一度実行して許可してください。

**`invalid choice: 'device'` のようなエラーが出る**
コマンド名の綴りが違います。正しくは `devices`（複数形）です。エラーメッセージに使用可能なコマンドの一覧が表示されるので、そちらを確認してください。

**`.\run.ps1` が「仮想環境が見つかりません」で止まる**
`.venv` フォルダがありません。[セットアップ](#2-インストール)の ② と ③ を実行してください。

**`python` が見つからないと言われる**
Python 3.11 以上をインストールし、インストーラーで「Add python.exe to PATH」にチェックを入れてください。インストール直後は新しいターミナルを開き直します。

**「録音の 100% が無音でした」と出る**
録音デバイスの選択が誤っているか、配信を再生していません。`.\run.ps1 devices` で正しいデバイス名を確認し、`config.toml` の `[recorder] device_name` に設定してください。

**長時間の録音で、途中から無音になっていた**
スリープや省電力でブラウザの再生が止まった可能性が高いです。**PCを復帰させただけでは配信の再生は戻らず、ページの再読み込みが必要**な場合があります。録音中は3分以上の無音を検知して警告を出すので、放置する場合もときどきログを確認してください。

**文字起こしが CPU で動いてしまう**
GPU用ライブラリが見つかっていません。`pip install nvidia-cublas-cu12 nvidia-cudnn-cu12` が済んでいるか確認してください。それでも解決しない場合は `-v` を付けて実行するとログに理由が出ます。

**VRAM が足りないというエラーが出る**
`config.toml` の `transcriber.model` を `medium`、`compute_type` を `int8_float16` に下げてください。

**`ffmpeg: 見つかりません` と表示される**
ffmpeg をインストールした直後は、新しいターミナルを開き直してください。それでも見つからない場合、音声は WAV のまま保存されます（動作自体には支障ありません）。

**要約だけ失敗した**
文字起こしは保存済みです。`.\run.ps1 summarize "archive\対象フォルダ"` で要約だけ再実行できます。

**全画面にならない**
プレイヤーの読み込みが終わる前に全画面ボタンを押そうとすると失敗します。2秒間隔で5回まで自動で再試行し、それでも駄目な場合は Fullscreen API を直接呼ぶため、通常は成功します。それでも失敗する場合はログに理由が出ます（「プレイヤーがまだ表示されていません」「ボタンが見つかりません」など）。全画面が不要なら `config.toml` の `[browser] fullscreen = false` にしてください。

**要約が途中で終わっている**
出力上限に達しています。`summary.md` の冒頭に警告が入り、実行時のログにも「要約が途中で終了しました」と出ます。`config.toml` の `[summarizer] max_tokens`（既定8000）を増やし、`.
un.ps1 summarize "archive\対象フォルダ" --force` でやり直してください。長時間配信で話題数が多い回で起こりえます。

**要約の内容が気に入らない／別のモデルで試したい**
`config.toml` の `summarizer.model` を変更し、`.\run.ps1 summarize "archive\対象フォルダ" --force` を実行してください。文字起こしはやり直されないため、GPUの再処理時間はかかりません。

**「すでに別のプロセスが実行中です」と出て起動できない**
`watch` または `capture` が既に動いています。**同時に複数動かすと同じ録音ファイルを奪い合って録音が壊れる**ため、意図的に止めています。メッセージに表示されたPIDを `Stop-Process -Id <PID> -Force` で終了してから起動し直してください。異常終了でロックが残った場合は、次回起動時に自動で引き継ぐため対処は不要です。

**「このアーカイブはまだ視聴できません」と出る**
配信終了後の変換処理が完了していません。`.\run.ps1 archives` で「未公開」が「1時間47分」のような表示に変われば取り込めます。

**PCがスリープして配信を録り逃した**
`config.toml` の `[power] prevent_sleep` が `false` になっていないか確認してください。既定は `true` で、`watch` 起動時のログに「スリープを抑止します」と出ます。出ていない場合は設定が無効か、抑止に失敗しています（その場合は警告ログが出ます）。なお、`watch` を実行していない間はスリープを抑止しません。

**録画した映像の配信部分が黒い**
保護された再生経路が使われています。回避策は取らず、`config.toml` の `[video] enabled = false` にして音声のみの運用に戻してください。

**録画に別のモニタが写っている**
`.\run.ps1 displays` でディスプレイ番号を確認し、`[video] display_index` を変更してください。縦置きモニタは回転前の解像度で表示されることがあります。

**映像と音声がずれている**
終了時の長さの差から自動補正していますが、差が30秒を超える場合は補正を行いません（ログに警告が出ます）。その場合は録画の開始・停止のタイミングを確認してください。

**ディスクの空きが足りなくなった**
`.\run.ps1 cleanup --dry-run` で削除対象を確認し、`[retention] video_days` を短くしてから `.\run.ps1 cleanup` を実行してください。`[video] height` を下げるのも有効です。

**アーカイブの取り込みが無音になった**
`capture` を実行してからブラウザで再生を始めましたか。再生していない間は無音が記録されます。また、再生前に自動停止時間が来てしまわないよう、再生開始は速やかに行ってください。

**アーカイブの取り込みが途中で切れた**
`--minutes` で時間を明示的に指定してください（既定ではAPIが返す尺＋120秒で自動停止します）。`[recorder] max_hours`（既定8時間）を超えると強制停止する点にも注意してください。
